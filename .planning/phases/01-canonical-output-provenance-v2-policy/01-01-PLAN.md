<action>
Create CommonJS module backend/modules/canonicalOutput.js exporting `POLICY_VERSION = 'codex-v2'`, `CANONICAL_TAGS`, `parseLegacyLine(line, context)`, `validateCandidate(candidate, context)`, `validateEvents(candidates, context)`, `toLegacyScriptEvent(event)`, `normalizeText(text)`, and `createCanonicalEventId(event)`. Parse exactly `[integer][v1|v2|v3|txt|trans] text`; do not accept markdown or alternate tags. Produce canonical events with fields `id`, `timestamp`, `text`, `tag`, `legacyVerbosity`, `provenance`, `policyVersion`, `validationStatus`, `validationReasons`, and `ttsEligible`. Require provenance kind `visual`, `screen_text`, or `foreign_dialogue`, with frame evidence for visual/screen_text and a confirmed dialogue interval for foreign_dialogue. Reject empty text, non-finite/negative/out-of-range timestamps, unsupported tags/provenance, and text exceeding the configured sentence limit without clamping or silent correction. Apply language gates for `korean`, `foreign`, `mixed`, and `unknown`; require `[trans]` to be needed confirmed foreign speech, require `[txt]` to have visible frame evidence independent of dialogue, and suppress Korean/unknown transcript translation. Normalize whitespace and punctuation for deterministic IDs and duplicate comparison. Return structured `{accepted, quarantined, rejected, reasons}` results; use quarantine for semantically ambiguous evidence or overlap and never mark it TTS eligible. Make `validateEvents` run deterministic time-window/normalized-text duplicate checks and dialogue occupancy checks while allowing a foreign translation to reference its own source interval. `toLegacyScriptEvent` must return exactly `id`, numeric `timestamp`, `text`, and legacy `verbosity` values `v1`, `v2`, `v3`, `text`, or `translation`, plus non-breaking `validationStatus`, `ttsEligible`, `policyVersion`, and provenance fields.
</action>

<threat_model>
<threat id="T-01" severity="high">Untrusted model output, title, caption, OCR, or visible text could inject instructions or unsupported tags into playable output. Mitigation: strict line parser, allowlisted tags, evidence/provenance requirements, and no prompt-derived authority in the validator.</threat>
<threat id="T-02" severity="high">A semantically unsafe or Korean-duplicate event could reach TTS if it is merely syntactically valid. Mitigation: language, duplicate, dialogue occupancy, validation status, and explicit ttsEligible gates are asserted in pure tests.</threat>
<threat id="T-03" severity="medium">Evidence or quarantine reasons could contain unbounded raw sensitive text. Mitigation: bound reason/detail fields and keep canonical evidence references structured; do not log full prompts or captions in tests.</threat>
</threat_model>
