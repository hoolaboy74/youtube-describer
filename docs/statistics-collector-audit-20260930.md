# 운영 통계 수집기 범위 및 정확성 감사

검토일: 2026-09-30 KST. 대상: `.agents/skills/analyze_system_stats/scripts/stats_collector.js` 및 월간 후원 리포트 생성 도구.

## 결론

현재 수집기는 서비스의 모든 통계를 수집하지 않는다. 운영 DB의 내부 SQLite 테이블을 제외한 20개 테이블 중 9개만 조회하며, 그중 일부도 잘못된 지표 이름·기간 필터·중복 집계로 해석된다. 조회 테이블 비율은 완성도 비율이 아니다. 설정 테이블 등은 지표가 아니라 집계 설정의 근거로 다뤄야 한다.

`api_requests`는 이미 조회한다. 다만 회원 IP 추정용 배열로만 사용하며 API 경로별 이용량, Q&A 요청량, 로그인·오류·취소 흐름 등을 독립적인 지표로 출력하지 않는다. Q&A 비용은 현재 `api_costs`에 함께 저장되므로 총비용에 일부 포함될 수 있지만, 설명 생성 비용과 분리하지 않는다. “Q&A 비용이 전혀 포함되지 않는다”는 단정도 정확하지 않다.

## 확인 범위와 증거

- 로컬 main의 수집기와 실제 서비스 코드를 읽고 test 브랜치의 코드베이스 지도 7개 문서를 현행화했다. 소스 변경 및 운영 배포는 수행하지 않았다.
- 운영 `mom`의 `/app/youtube-describer/backend/db/cache.db`를 읽기 전용으로 조회했다. 실제 테이블·컬럼, 행 수, 비용·Q&A 상태별 집계, 로그 파일 목록을 확인했다.
- 운영의 `backend/database.js`, `backend/routes.js`, `backend/logger.js`, `backend/modules/qaRoutes.js`, `backend/modules/qaGeneration.js` SHA-256이 로컬 main과 일치했다. 따라서 아래 발견은 단순한 미배포 개발 코드에 대한 추측이 아니다.
- 개인정보·질문/답변 본문·토큰 없이 저장한 증거: `.planning/features/statistics-audit/production-inventory-20260930.json`.
- 운영 수집기는 서버에 배포된 파일이 아니라 로컬에서 SSH로 생성한 쿼리를 보내는 도구다. 서버에는 해당 스킬 파일이 존재하지 않았다.
- 별도 테스트 서버 DB는 조사하지 않았다. 월별 수치는 조회 시점까지 보존된 행을 대상으로 하며 삭제된 과거 데이터의 복원을 보장하지 않는다.

## 정확성 문제

### 1. 기간과 시간대: 모든 월간 지표에 영향을 줄 수 있음

`stats_collector.js:54`는 요청 시작일을 그대로 적용하고, 최초 가입 시각을 출력만 한다. 스킬 문서의 “최초 가입 이후 강제 하한선”과 실제 동작이 다르다. 기본값은 1970년이다. 입력 날짜도 엄격한 실제 달력 날짜 검증이 아니며 역전 기간 검사가 없다.

DB의 `CURRENT_TIMESTAMP`는 UTC이다(`backend/database.js:53` 이후 스키마). 그러나 SQL은 KST로 표시한 날짜 문자열을 그대로 비교한다. 새 비용 행은 `recordGeminiUsage`가 ISO UTC 문자열을 쓰며, 옛 SQL 날짜 형식과 섞여 있다(`backend/database.js:1003`). 문자열 비교 대신 UTC 순간으로 정규화한 반개방 범위 `[시작, 다음날 00:00)`가 필요하다.

Nginx 파서는 이미 타임존 offset을 제거한 순간에 다시 9시간을 더한 뒤 `+09:00`으로 해석된 경계와 비교한다(`stats_collector.js:591`). 경계가 9시간 어긋난다. 일별 버킷 역시 실제 KST 날짜로 계산해야 한다. 최초 8월 원문에 7월 31일 일별 AAU가 나타나는 것을 확인했다.

운영 DB로 직접 재검증한 8월 KST 합계는 등록 영상 224개, 성공 상태 201개, 성공 영상 길이 187,729초, 비용 $129.080974, 신규 회원 19명이다. 기존 수집기는 길이 188,642초, 비용 $129.845를 출력했다. 개수가 같아도 기간 경계의 대상 영상은 달라질 수 있다.

### 2. API/시청 상관 분석: 유효하지 않은 Date와 잘못된 IP 승격

쿼리는 `strftime('%Y-%m-%dT%H:%M:%SZ', ...)`로 이미 `Z`가 있는 날짜를 반환한다(`stats_collector.js:373`, `389`). 이를 다시 `+'Z'`로 파싱해 `...ZZ`가 된다(`stats_collector.js:500`, `510`). Date가 NaN이므로 5초/15초 상관 매칭이 성립하지 않는다.

인증 API 접근 IP를 성공 여부와 기간 확인 없이 회원 IP로 승격하고, 수집 시점의 `lastLoginIp`를 과거 기간에도 사용한다. 로그인 페이지 접근만으로 인증 성공을 알 수 없고 NAT·공유 IP·IP 변경도 있다. 또한 매 Nginx 행마다 전체 API 배열에 `.some()`을 수행하여 기록 수의 곱에 비례하는 비용이 든다. 실제 8월 수집에 수분이 걸렸다. 시간/IP 색인과 기간 제한이 필요하다.

### 3. 시청·좋아요·요청 수: 보존 상태를 이벤트 횟수로 표시

`backend/database.js:1687`의 시청 저장은 `(userId, videoId)` 충돌 시 마지막 시간을 갱신하고 회원당 최근 20개만 남긴다. 이 테이블의 월별 COUNT는 실제 재생 횟수나 정확한 월간 활성 회원 수를 복원하지 못한다. 8월 기록이 9월 시청으로 갱신/삭제될 수 있어 과거 보고서가 실행 시점마다 바뀐다.

`backend/database.js:1715`의 즐겨찾기는 취소 시 행 삭제다. 월간 COUNT는 클릭 수가 아니다. 영상 생성도 `videos`의 현재 행을 세므로 API 요청 횟수·재시도·기존 영상 요청을 포함하지 않는다. 지표 명칭을 보존된 상태에 맞추거나 별도 불변 이벤트 원장이 필요하다.

### 4. 비용과 JOIN: Q&A 도입 후 중복·혼합 위험

최다 요청자 쿼리는 영상과 `api_costs`를 직접 JOIN한 상태에서 COUNT와 duration SUM을 한다(`stats_collector.js:180`). 영상 하나에 설명 생성·Q&A 비용 행이 여러 개 있으면 요청 수와 영상 시간이 부풀려진다. 지연 시간도 모든 비용 행의 생성 시간을 완료 시간처럼 사용한다(`stats_collector.js:414`). 몇 주 뒤 Q&A 호출이 생성 지연/이상치로 계산될 수 있다. 비용 누락 검사도 영상별 비용을 사전 집계해야 한다.

최고 비용 영상 Top 5는 영상별 합계가 아니라 개별 비용 행 Top 5다(`stats_collector.js:288`). 전체 비용을 성공 해설 건수/시간으로 나누는 후원 보고서도 Q&A 비용을 섞으면 설명 생성 단가가 아니게 된다.

새 비용은 `api_costs` 상세 원장과 `qa_user_daily_costs` 요약에 함께 기록된다(`backend/database.js:953`). 두 원장을 단순 합산하면 중복 과금 통계가 된다. 총비용은 상세 원장을 기준으로 하고 요약은 대조에만 사용해야 한다. 검색 무료 한도 원장도 별도 비용 원장이 아니다.

### 5. TTS HIT율과 로그 누락: 없는 증거를 성공으로 표시

기간 내 남아 있는 파일의 mtime 개수를 캐시 MISS 호출 수로 간주한다. 삭제·재생성·동시 요청·캐시 루트 변경·Q&A 캐시를 반영하지 못한다. `1 - 파일수/요청수`는 음수가 될 수도 있으며, 요청이 0이면 “100% HIT”로 출력한다(`stats_collector.js:1293`). 관측 불가 또는 N/A로 표시해야 한다.

Nginx 파일 읽기/압축 파싱 오류를 빈 catch로 무시한다(`stats_collector.js:787`). 백엔드 로그도 없는 날짜 파일을 경고하지 않는다. “로그 없음”과 “요청/오류 0”을 구분하지 못한다. 출처별 보존기간·읽기 실패·파일 개수·관측 가능 날짜를 보고서에 포함해야 한다.

### 6. 월간 생성 도구의 파서 오류

`monthly-sponsor-report-deploy/scripts/build_monthly_report.py`는 인증 분포 블록 종료를 `누적 회원 인증 경로 분포:`로 찾지만 실제 헤더는 `누적 회원 인증 경로 분포 (전체 기간):`이다. 블록이 비어 인증 회원을 0명으로 표시한다. 관리자 수동 승인도 신규 인증 합계에서 빠진다. 문자열 순차 치환은 이전 월 값 일부가 남거나 치환 결과가 다시 바뀔 위험이 있다. 원자료 기본값 0은 누락/미수집과 실제 0을 구분하지 못한다.

## 운영에서 실제 관측한 누락

아래 값은 2026-09-30 조회 시점까지 보존된 9월 자료이며 9월 말 전체 실적을 뜻하지 않는다.

- Q&A 요청 영수증 453개: completed 420, canceled 18, failed 15. usageStatus=unconfirmed 18개. 이 18개가 모두 유료 사용이라는 뜻은 아니며 비용 확인이 끝나지 않은 상태다.

- Q&A 캐시 작업 현재 549개: queued 267, downloading 134, ready 129, retryable_failed 19. 프레임 70,202개, 자막 자산 124개. 이는 현재 상태로서 월간 작업 발생 횟수가 아니다.
- 검증 격리 이벤트 239개. 사유별 집계 가능하지만 수집기는 읽지 않는다.
- 보관 9월 일별 로그 29개에서 QA-MEDIA 3,575개, QA-GENERATION 1,343개가 확인된다. window_hit 200, window_miss 29 등 구조화된 이벤트가 이미 있는데 기능별 집계에 쓰지 않는다. 날짜 파일 수가 달력 일수와 같지 않으므로 로그 완전성은 별도 점검 대상이다.
- API 로깅은 2026-07-20 04:03:51 UTC부터 존재한다. 그 이전에는 같은 정밀도의 API 기반 통계를 소급 생성할 수 없다.
- 8월 자료에는 Q&A 비용/영수증/태그 로그가 관측되지 않았다. 9월 누락 지표를 8월 실적으로 채우면 안 된다.

## 개편 권장 순서

1. **정확성 기반**: KST 범위→UTC 반개방 경계, 날짜 정규화, 중복 JOIN 제거, double-Z 수정, 출처 완전성/누락 경고, 지표 정의 수정, 최초 가입 하한선 계약 정리.
2. **현재 데이터로 추가 가능**: API 기능별 요청·회원/비회원·일별 고유 사용자, Q&A receipt 상태·비용 대조·취소·불확실 사용량, 기능별 비용·검색·토큰, QA 로그 이벤트·캐시 상태, 격리 사유, 인증 이력, 후원금.
3. **추가 계측 필요**: 실제 재생 시작/진행/완료, 반복 시청·즐겨찾기 클릭/취소·수정/삭제 이벤트, HTTP method/status/응답 시간/requestId, TTS HIT/MISS/합성량·비용, 사용자 체감 첫 음성/재시도/단계별 지연, 월말 스냅샷. 현재 저장되지 않은 과거 이벤트는 복원할 수 없다.

API 로그에는 `apiPath`만 있고 method/status/duration/requestId가 없다. 동일 경로의 GET/POST를 구분할 수 없으며 실패/성공은 Nginx·별도 이벤트와 제한적으로만 대조할 수 있다. 요청 기록을 그대로 성공 사용자 행동 수로 취급하지 말아야 한다.

최종 산출물은 구조화 JSON(지표 값/단위/정의/근거/기간/관측상태)과 TXT/후원 HTML로 분리하고, 새 테이블·엔드포인트를 발견하면 coverage manifest에서 검토되지 않았음을 경고하도록 권장한다. 후원 본문에 사용자 식별자·IP·질문/답변 본문·원시 오류를 넣지 않는다.

## 필요한 검증

- UTC SQL/ISO/epoch 혼합, KST 월 첫날·마지막 순간·다음날 제외, leap day/역전 기간·가입 하한선.
- 영상 하나에 설명 비용 2행/Q&A 비용 여러 행이 있어도 영상수·duration·설명 단가가 중복되지 않는 fixture.
- receipt 중복·취소·실패·usage unconfirmed와 상세/일별 비용 불일치.
- 재시청 upsert·최근 20개 정리·즐겨찾기 삭제가 이벤트 횟수로 출력되지 않는 fixture.
- 압축/손상/누락/권한 없는 로그 파일, 기능 비활성/테이블 없음/관측 이전의 N/A 표시.
- TTS 요청 0, 파일 삭제/재생성, 일반/Q&A 캐시 분리 및 실제 HIT/MISS 이벤트.
- 스폰서 본문의 원자료 대조, 인증 헤더 파싱·관리자 승인, 개인정보 제외 및 이미지 참조.

현재 수집기의 전체 기능 개편은 이 감사에 포함되지 않는다. 8월 산출물에는 임시 읽기 전용 실행 도구로 기간/파싱 오류를 보정하고, 보존 이력·현재 상태·IP 추정치의 한계를 명시한다. 서비스 소스와 공유 스킬은 변경하지 않았다.
