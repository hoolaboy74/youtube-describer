# Matrix Test Plan: Local vs Remote Video and Prompt Anomaly Investigation

본 문서는 로컬 개발 환경(Mac)과 원격 운영 서버(mom) 간의 비디오 소스 일치성, 프레임 추출 메커니즘, AI 프롬프트 정책, 이미지 해상도 변수가 AI 대본 생성(특별히 번역 자막 누락 구간)에 미치는 영향을 규명하기 위한 다차원 교차 검증(Matrix Test) 계획서입니다.

## 1. 테스트 목적 및 범위
- 대상 영상: YouTube Clip [OT0wMk7yIEo](https://www.youtube.com/watch?v=OT0wMk7yIEo)
- 검증 구간: 160초 ~ 184초 (맷 데이먼 인터뷰 구간)
- 핵심 대조군: 로컬 개발 장비(Mac) vs 원격 운영 서버(mom, Ubuntu)

## 2. 테스트 매트릭스 설계

### 차원 0: 비디오 소스 무결성 검증 (0. 준비 단계)
- 로컬과 원격 각각에서 `yt-dlp`를 실행하여 사용 가능한 포맷 리스트(`yt-dlp -F`)를 덤프 및 비교합니다.
- 특정 포맷 `bestvideo[height<=360][acodec=none][ext=mp4]`을 지정하여 비디오를 다운로드합니다.
- 다운로드된 두 비디오 파일의 바이트 단위 크기(size) 및 SHA-256 해시를 산출하여 일치 여부를 판별합니다.
- 만약 해시가 일치하면 비디오 소스 분기 가설은 즉시 기각됩니다.

### 차원 1: 프레임 추출 메커니즘 비교
- **방식 A (기존 방식)**: `select='isnan(prev_selected_t)+gte(t-prev_selected_t,2)'` 필터 및 `-vsync vfr` 기반으로 영상의 2초 간격마다 무조건 디코딩하여 추출합니다.
- **방식 B (현재 방식)**: 하이브리드 추출 (`extractKeyframesHybrid`). `-skip_frame nokey`로 고속 I-frame 추출 후 2초 간격 갭에 대해 `-ss Seeking`을 수행하여 정밀 백필(Backfill)합니다.
- 비교 지표: 추출된 전체 프레임 수, 프레임별 정확한 타임스탬프 일치율, 그리고 특정 타임스탬프(예: 166초, 172초)에서의 이미지 픽셀 해시(pHash) 비교.

### 차원 2: AI 프롬프트 템플릿 대조
- **템플릿 1 (단순 OCR 모드)**: 페르소나 없이 "화면에 타임스탬프와 함께 보이는 모든 자막 텍스트(OCR)를 순서대로 한글로 읽으시오"라는 극도로 단순화된 프롬프트.
- **템플릿 2 (이전 프롬프트)**: 2026년 7월 31일 이전 버전 (`f0bed6a` 커밋)의 프롬프트 템플릿. (한국어 대사 판단 및 번역 자막 존댓말 순화 낭독 규칙 적용)
- **템플릿 3 (현재 프롬프트)**: 현재 버전의 프롬프트 템플릿. (로컬 랭귀지 감지 결과 접목 및 대사 스킵 룰 엄격화 적용)

### 차원 3: AI 입력 해상도 분기
- **Low Resolution**: 640px 이하 리사이징 이미지 전송 (`scale=640:-1`)
- **High Resolution**: 360p 비디오의 원본 크기 그대로 혹은 720p 이상 비디오 소스에서 추출한 미가공 원본 해상도 전송.

## 3. 원격 서버 테스트 배포 및 실행 전략
- 테스트 시나리오를 통합 제어하고 결과를 JSON 및 CSV 보고서로 출력하는 독립 테스트 구동기(`test_matrix_runner.js`)를 로컬에서 작성합니다.
- 해당 구동기 및 테스트에 필요한 프롬프트 에셋 파일들을 `scp` 명령어를 통해 원격 서버(`chacha@mom`)로 복사합니다.
- 로컬과 원격 서버에서 각각 테스트 구동기를 실행하여 격리된 폴더에 결과를 기록합니다.
- 산출된 결과 데이터를 비교하여 원격과 로컬 간의 불일치를 일으키는 트리거 변수를 최종 특정합니다.
