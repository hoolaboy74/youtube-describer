# 인터랙티브 비디오 Q&A 시스템 기술 사양서 (v2.0)

본 문서는 시각장애인 사용자가 유튜브 영상을 시청하는 도중 질문을 입력하여, 실시간으로 화면 내 시각적 디테일에 대한 해설을 제공받는 양방향 질의응답 시스템의 **최적화된** 사양을 다룹니다.

---

## 1. 개요 (Overview)

*   **목표**: Gemini 2.5 Pro의 대규모 컨텍스트 윈도우를 활용하여, 추가적인 영상 처리 지연 없이 즉각적인 화면 질의응답이 가능한 시스템 구축.
*   **전략적 변화**: 
    *   **입력**: 음성 녹음(Audio) 방식에서 **텍스트 입력(Text Input)** 방식으로 변경하여 데이터 전송 및 처리 속도 극대화. (추후 클라이언트 STT 도입 고려)
    *   **자원**: 실시간 프레임 추출 대신 **기 생성된 2초 간격 프레임**을 100% 재사용.
    *   **응답**: 질문 시점까지의 모든 시각/텍스트 데이터를 컨텍스트로 주입하여 답변의 정확도 확보.

---

## 2. 시스템 아키텍처 및 데이터 흐름 (Architecture)

```
[FE: Text Input] ──(Question Text)──> [BE: Q&A API] ──(Query DB/Disk)──> [Frames & AD Script]
                                               │
                                       (Rich Context Feed)
                                               │
                                               ▼
                                       [Gemini 2.5 Pro] ──(Text Answer)──> [FE: TTS Playback]
```

### A. 클라이언트 (Frontend)
1.  **입력 인터페이스**: 영상 시청 중 특정 키(예: `Enter` 또는 `Q`)를 누르면 입력창 활성화 및 영상 일시정지.
2.  **질문 전송**: 사용자가 입력한 텍스트 질문과 현재 재생 시점(`currentTime`)을 백엔드로 전송.
3.  **결과 수신**: 백엔드로부터 온 텍스트 답변을 스크린리더 또는 자체 TTS를 통해 즉시 재생.

### B. 백엔드 (Backend)
*   **엔드포인트**: `POST /api/video-qa`
*   **Payload**:
    ```json
    {
      "videoId": "string",
      "currentTime": 125.5,
      "question": "방금 칠판에 쓴 공식 알려줘"
    }
    ```
*   **컨텍스트 조합 (The Context Builder)**:
    1.  **시각 정보**: `currentTime`과 가장 가까운 프레임부터 시작하여, 이전 맥락을 포함한 $N$개의 추출 프레임(JPG) 로드.
    2.  **텍스트 정보**: 유튜브 자막(Subtitles) + 이미 생성된 화면 해설(AD Script) 중 해당 시점까지의 내용 취합.
    3.  **프롬프트 구성**: `[시스템 프롬프트] + [자막/AD 맥락] + [이미지 시퀀스] + [사용자 질문]`

## 3. 핵심 엔지니어링 최적화 (Optimization)

### A. 프레임 영구 보관 및 인덱싱 (Frame Persistence)
*   기존에는 영상 처리 완료 후 임시 프레임을 삭제했을 수 있으나, Q&A 기능을 위해 `public/frames/{videoId}/` 경로에 JPG 파일들을 영구 또는 세션 종료 시까지 보관합니다.
*   파일명은 `frame-0060.jpg` (60초 지점)와 같이 타임스탬프 기반으로 저장하여 DB 조회 없이 즉각적인 파일 매칭이 가능하도록 합니다.

### B. 컨텍스트 윈도우 전략 (Context Windowing)
*   Gemini 2.5 Pro의 200만 토큰을 활용하되, 응답 속도를 위해 질문 시점 $T$를 기준으로 **최근 2~5분간의 프레임과 자막**을 집중적으로 배치합니다.
*   이미 생성된 화면 해설(AD)을 포함함으로써 AI가 이전에 설명했던 내용과 중복되지 않거나, 이전 설명을 보완하는 답변을 하도록 유도합니다.

### C. 레이턴시 제거 (Zero-Latency Strategy)
*   **On-Demand 추출 제거**: `yt-dlp`, `ffmpeg` 실행 과정을 생략하므로 서버 부하가 획기적으로 줄어들고 응답 시간이 Gemini API 라운드트립 시간(약 1~2초)으로 단축됩니다.
*   **텍스트 기반 통신**: 바이너리 오디오 전송에 따른 오버헤드를 제거하여 네트워크 지연을 최소화합니다.

---

## 4. UX 및 접근성 (UX & Accessibility)

*   **스크린리더 최적화**: 입력창 활성화 시 포커스를 즉시 이동시키고, 답변 수신 시 `aria-live="assertive"` 또는 자동 TTS 재생을 통해 사용자가 즉각 피드백을 받게 합니다.
*   **빠른 질문(Quick Suggestions)**:
    *   "방금 나온 자막 읽어줘"
    *   "칠판 글씨 자세히 설명해줘"
    *   "지금 저 사람 표정 어때?"
    와 같은 빈번한 질문은 단축키나 버튼으로 제공하여 타이핑 피로도를 줄입니다.

---

## 5. 향후 논의 및 구현 아젠다 (Open Items)

1.  **프레임 보관 정책**: 스토리지 용량 관리를 위해 영상 처리 완료 후 일정 기간(예: 30일) 뒤에 프레임을 자동 삭제하는 로직 필요.
2.  **프롬프트 엔지니어링**: 질문 시점 이전의 시각 정보를 AI가 얼마나 깊게 파악해야 하는지에 대한 골든 타임셋(예: 최근 5분) 검증.
3.  **클라이언트 STT 브릿지**: 타이핑이 어려운 사용자를 위해 브라우저 내장 Web Speech API를 사용하여 음성을 텍스트로 변환 후 전송하는 기능 추가 검토.
