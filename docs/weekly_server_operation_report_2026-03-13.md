## 1. 운영 요약 (Executive Summary)
이번 주는 전주 대비 실제 고유 방문자 수는 감소하였으나, 사용자당 활동성(Request per IP)이 폭발적으로 상승하며 서비스에 대한 매우 높은 충성도를 확인할 수 있었던 한 주였습니다. 검색엔진 봇 및 크롤러 트래픽을 제외한 주간 실질 방문자(Unique IP)는 **1,295명**으로 전주(2,260명) 대비 **약 42.7% 감소**하였으나, 전체 Nginx 요청 수는 **36,355건**으로 전주(21,291건) 대비 **70.8% 급증**하였습니다.

시스템 안정성 측면에서 **영상 생성 성공률은 76.2%**로 전주(80.0%) 대비 **3.8%p 하락**하였습니다. 이는 '임베드 불가' 영상과 '30분 시간 제한 초과' 영상에 대한 반복적인 시도가 주요 원인으로 분석됩니다. 건당 생성 비용은 **$0.252**로 전주($0.246)와 비슷한 수준을 유지하며 안정적인 비용 구조를 보이고 있습니다.

*   **총 영상 생성 시도:** 122 건 (▼ 9.6%)
*   **총 영상 생성 성공:** 93 건 (성공률 76.2%, ▼ 3.8%p)
*   **총 API 비용 (Gemini):** $23.40 USD (건당 약 $0.252)

## 2. 상세 운영 지표

### 2.1 트래픽 및 사용자 활동
*   **사용자당 활동성 폭발적 증가:** 실제 방문자 한 명당 평균 요청 수가 전주 약 9회에서 이번 주 **약 28회**로 3배 이상 증가했습니다. 이는 서비스의 핵심 사용자층이 형성되었으며, 이들이 서비스 내에서 매우 활발하게 영상을 시청하고 해설을 생성하고 있음을 의미합니다.
*   **실질 방문자 분석:** 고유 IP 중 약 14.5%가 검색엔진 봇 및 보안 스캐너 트래픽으로 확인되어 이를 제외한 실질 사용자 지표를 산출하였습니다. 방문자 수는 감소세이나 헤비 유저의 비중이 크게 늘어난 것으로 보입니다.
*   **TTS 활용도 지속:** TTS 호출 건수는 5,680건으로 방문자 수 감소에 따라 동반 하락하였으나, 실질 방문자당 평균 약 4.4회의 TTS를 호출하고 있어 활용도는 여전히 높습니다.

### 2.2 영상 처리 및 비용 효율
*   **비용 안정화:** 건당 평균 비용이 $0.252로 유지되고 있습니다. 1400원의 환율을 적용할 때 주간 총 API 지출액은 약 32,760원 수준입니다.
*   **실패율 및 원인 (총 29건 실패):**
    *   **임베드 불가 (10건, 34.5%):** 유튜브 공식 정책에 따라 외부 사이트 재생이 제한된 영상들입니다. (예: `ExMsjhci`, `V2_ndlEX` 등)
    *   **시간 제한 초과 (7건, 24.1%):** 30분 이상의 긴 영상에 대한 처리 시도입니다. (예: `CAUkNSF-`, `WyuzTQJE`, `vDbZjeIK` 등)
    *   **yt-dlp 네트워크 오류 (6건, 20.7%):** `SSL: UNEXPECTED_EOF_WHILE_READING` 에러가 관찰되었습니다. 프록시 네트워크의 일시적인 불안정성으로 추정됩니다.
    *   **검색 파싱 오류 (6건, 20.7%):** 고질적인 `browseId` 파싱 실패 사례입니다. "갤럭시s26 개통" 등 특정 검색어에서 발생했습니다.
    *   **콘텐츠 정책 거부 (2건, 6.9%):** `PROHIBITED_CONTENT`로 인한 생성 거절 사례입니다.

### 2.3 시스템 오류 및 대응
*   **봇 트래픽 필터링 로직 도입:**
    *   고유 IP 집계 시 실질 사용자와 무관한 검색엔진(Google, Bing 등) 및 크롤러 트래픽을 제외하도록 분석 로직을 강화하였습니다. 이를 통해 향후 더욱 정밀한 사용자 행동 분석이 가능해졌습니다.
*   **검색 엔진의 한계:**
    *   공식 API 도입 전까지 `youtube-sr`의 불안정성으로 인한 검색 실패가 지속되고 있습니다.

## 3. 종합 의견 및 제안
1.  **사용자 필터링 강화 제안:** '임베드 불가' 영상의 경우 처리를 시작하기 전에 미리 감지하여 사용자에게 안내함으로써 불필요한 서버 리소스 소모를 방지해야 합니다.
2.  **검색 안정성 개선 시급:** 성공률 하락의 보이지 않는 주범인 검색 파싱 오류를 해결하기 위해, 68차/69차 개선 사항의 연장선상에서 공식 API 전면 도입을 우선순위로 검토해야 합니다.
3.  **충성 고객 중심 UX 강화:** 인당 요청 수가 급격히 늘어난 만큼, 자주 시청하는 카테고리 추천이나 시청 기록 관리 등 헤비 유저를 위한 편의 기능을 강화할 시점입니다.
