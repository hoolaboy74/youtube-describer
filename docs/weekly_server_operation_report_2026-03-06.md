## 1. 운영 요약 (Executive Summary)

다만, 시스템 안정성 면에서 **영상 생성 성공률은 80.0%**로 전주(89.6%) 대비 하락하였습니다. 이는 유튜브 검색 결과 페이지 구조 변경에 따른 고질적인 파싱 오류(browseId)와 더불어, AI 모델의 콘텐츠 정책에 따른 생성 거부(Prohibited Content) 사례가 빈번하게 발생했기 때문으로 분석됩니다. 긍정적인 부분은 건당 생성 비용이 **$0.246**으로 전주($0.304) 대비 **약 19% 감소**하며 비용 효율성이 개선되었다는 점입니다.

*   **총 영상 생성 시도:** 135 건 (▲ 8.0%)

## 2. 상세 운영 지표

### 2.1 트래픽 및 사용자 활동
*   **사용자 유입 급증:** 주간 Unique IP가 2,200명을 넘어서며 서비스 인지도가 다시 상승하고 있음을 확인했습니다. 특히 3월 2일(월)과 3월 5일(목), 6일(금)에 방문자가 집중되었습니다.
*   **TTS 활용도 상승:** 방문자 수 증가에 비례하여 TTS 호출 건수도 7,500건을 상회했습니다. 방문자당 평균 약 3.3회의 TTS를 호출하고 있어 안정적인 이용 패턴을 보이고 있습니다.

### 2.2 영상 처리 및 비용 효율
*   **비용 효율성 개선:** 건당 평균 비용이 $0.246로 낮아졌습니다. 이는 이번 주에 처리된 영상들의 평균 길이가 상대적으로 짧았거나, AI 프롬프트 최적화로 인한 토큰 사용량 조절이 효과를 거두고 있는 것으로 보입니다.
*   **실패율 및 원인 (총 27건 실패):**
    *   **콘텐츠 정책 거부 (11건):** `Response was blocked due to PROHIBITED_CONTENT`. 특정 주제나 시각적 요소가 포함된 영상에 대해 Gemini API가 생성을 거부하는 사례가 이번 주에 특히 많았습니다.
    *   **시간 제한 초과 (6건):** 30분 이상의 영상 처리 시도입니다. (예: NSmZczJV, BSYjRqvN 등)
    *   **임베드 불가 (6건):** 외부 사이트 재생이 차단된 영상입니다.
    *   **Gemini 503 오류 (3건):** 구글 API 서버의 일시적인 과부하로 인한 생성 실패입니다.
    *   **검색 파싱 오류 (다수):** 로그상에서 "샤이니 민호", "갤럭시 S26" 등의 검색어 입력 시 `browseId`를 읽지 못하는 에러가 여전히 빈번하게 발생하고 있습니다.

### 2.3 시스템 오류 및 대응
*   **유튜브 검색 파싱 이슈 지속:**
    *   검색 실패가 전체 성공률 하락의 보이지 않는 주요 원인입니다. 사용자가 검색 결과에서 영상을 선택하기도 전에 오류를 경험하게 되어 UX 측면에서 치명적입니다.
*   **콘텐츠 거부(Block) 대응:**
    *   사용자가 유해하지 않은 영상을 요청했음에도 AI가 과도하게 검열하여 거부하는 경우가 있는지 샘플 조사가 필요합니다.

## 3. 종합 의견 및 제안
1.  **검색 모듈 전면 개편 필요:** 현재 사용 중인 `youtube-sr` 라이브러리의 파싱 안정성이 매우 낮아졌습니다. YouTube 공식 Data API를 검색 단계에도 도입하거나, 보다 안정적인 스크래핑 라이브러리로의 교체를 시급히 검토해야 합니다.
2.  **정책 거부 가이드 제공:** 'Prohibited Content'로 인해 생성이 거부될 경우, 사용자에게 단순히 에러를 표시하기보다 어떤 유형의 콘텐츠가 제한될 수 있는지 안내하는 메시지를 강화하여 불필요한 재시도를 줄여야 합니다.
3.  **트래픽 대응 서버 리소스 모니터링:** 방문자 IP가 2,000명을 상회함에 따라 Nginx 요청 수도 주간 2만 건을 넘었습니다. 현재 서버 사양에서 CPU 및 메모리 점유율이 안정적인지 지속적인 모니터링이 필요합니다.
