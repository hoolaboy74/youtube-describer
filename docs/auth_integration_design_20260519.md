# [설계서] 시각장애인 전용 서비스 이용을 위한 통합 인증 체계 구축

**작성일:** 2026년 5월 19일  
**대상 서비스:** 뷰레이터 (ViewRator)  
**핵심 목표:** 공공 지원금 기반 서비스의 부정 사용 방지 및 시각장애인 접근성 최적화

---

## 1. 개요 (Overview)

본 문서는 공공기관의 후원을 받는 '뷰레이터' 서비스가 실제 시각장애인 사용자에게만 혜택이 돌아가도록 제한하기 위한 통합 인증 체계의 설계 방안을 기술한다. 기술적 화려함보다는 **법적 안전성(보안)**, **사용자 편의성(접근성)**, **운영의 지속 가능성**에 초점을 맞춘다.

### 1.1 핵심 원칙
1. **개인정보 최소 수집 (Zero-PII):** 주민등록번호 등 민감한 개인정보를 우리 서버에 저장하거나 처리하지 않는다.
2. **접근성 최우선 (UX-First):** 시각장애인이 스스로 수행하기 어려운 인증 절차(사진 촬영, 복잡한 텍스트 입력 등)를 지양한다.
3. **신뢰 위임 (Trust Delegation):** 이미 국가/기관으로부터 검증된 외부 커뮤니티나 복지 기관의 신용을 활용한다.

---

## 2. 인증 아키텍처 (Authentication Architecture)

다양한 사용자 환경을 고려하여 3단계의 하이브리드 인증 모델을 구축한다.

### 2.1 메인 채널: 외부 기관 연합 인증 (Federated ID)
국내 최대 시각장애인 커뮤니티(넓은마을, 실로암 등)와 시스템적으로 연동하는 방식이다.
- **방식:** 외부 기관 로그인 후 발급된 보안 토큰(JWT)을 통해 인증 상태를 전달받음.
- **장점:** 법적 리스크가 없고, 사용자가 추가 서류를 제출할 필요가 없음.

### 2.2 보조 채널: 바우처 코드(Voucher) 배포
오프라인 복지관이나 점자 도서관을 통해 일회성 인증 코드를 배포하는 방식이다.
- **방식:** 기관에서 배포한 코드(난수)를 앱 내에서 입력하여 활성화.
- **장점:** 디지털 소외 계층(고령자 등)이 오프라인 방문 시 쉽게 지원받을 수 있음.

### 2.3 예외 처리: 웹 기반 복지카드 업로드 및 수동 검수 (Human-in-the-loop)
위 두 방식이 모두 불가능한 특수 케이스를 위한 우회로이다.
- **방식:** 서비스 내 전용 업로드 페이지에서 복지카드 사본(주민번호 뒷자리 마스킹 필수)을 업로드하고, 관리자가 대시보드에서 확인 후 승인.
- **장점:** 별도의 외부 서비스 비용(카카오톡 채널 등)이 발생하지 않으며, 서비스 내에서 모든 프로세스를 완결할 수 있음.
- **주의사항:** 업로드된 이미지는 승인 즉시 서버에서 영구 삭제하여 개인정보 유출 위험을 원천 차단해야 함.

## 3. 기술적 세부 구현 (Technical Implementation)

### 3.1 토큰 기반 연동 (JWT Flow)
외부 기관(IdP)과 뷰레이터 서버 간의 안전한 통신을 위해 다음 흐름을 권장한다.

1. 사용자가 뷰레이터에서 "넓은마을 인증" 버튼 클릭.
2. 넓은마을 로그인 페이지로 이동하여 로그인 수행.
3. 넓은마을 서버는 로그인 성공 시, 뷰레이터와 공유된 비밀키로 서명된 **JWT** 생성.
   - Payload: `{ "verified": true, "uid": "hash_value", "exp": "timestamp" }`
4. 사용자를 뷰레이터 리다이렉트 URL로 돌려보내며 토큰 전달.
5. 뷰레이터 서버는 토큰의 서명을 검증하고 해당 계정을 `is_verified: true`로 업데이트.

### 3.2 데이터 최소화 전략
- **No Name, No RRN:** 사용자의 실명이나 주민등록번호를 일절 주고받지 않는다.
- **Signal Only:** 오직 "해당 기관의 정당한 회원인가?"에 대한 `YES/NO` 신호만 신뢰한다.

## 4. 파트너 기관 준비 사항 (Requirements for Partners)

협력 기관(넓은마을 등)은 성공적인 연동을 위해 다음 사항을 준비해야 한다.

### 4.1 기술적 요구사항
- **인증 페이지(Endpoint) 제공:** 뷰레이터 사용자가 로그인할 수 있는 웹 페이지.
- **JWT 생성 및 전송 로직:** 로그인 성공 후 뷰레이터가 지정한 URL로 토큰을 실어 리다이렉트하는 기능.
- **보안 키 관리:** 서명에 사용할 비밀키(Secret Key)를 안전하게 관리.

### 4.2 정책적 요구사항
- **개인정보 처리방침 업데이트:** 제3자(뷰레이터)에게 '인증 여부'를 제공한다는 문구 추가.
- **제휴 계약(MOU):** 데이터 제공 범위 및 법적 책임 소재 명시.

---

## 5. 기대 효과 (Expected Outcomes)

1. **보안성:** 주민번호 등 민감 정보 유출 위험 원천 차단.
2. **신뢰성:** 공공기관 스폰서에게 국가 인가 기관을 통한 엄격한 통제 명분 제공.
3. **접근성:** 시각장애인 사용자가 별도의 증빙 서류 없이 기존에 쓰던 아이디로 즉시 이용 가능.
4. **확장성:** 향후 다른 장애인 단체나 글로벌 서비스로의 연동 확장이 용이함.
