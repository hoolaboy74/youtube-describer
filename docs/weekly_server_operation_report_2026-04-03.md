## 2. 상세 운영 지표

### 2.1 트래픽 및 사용자 활동
*   **충성 고객 기반 강화:** 고유 방문자 수는 소폭 감소했으나 TTS 호출량이 크게 늘어난 점은 고무적입니다. 이는 화면 해설의 품질이 실 사용자들의 시청 경험을 만족시키고 있음을 시사합니다.
*   **트래픽 안정화:** 전체 Nginx 요청 수는 감소했으나 이는 불필요한 크롤링이나 외부 봇 트래픽의 감소에 기인한 것으로 보이며, 실제 서비스 이용 지표인 TTS 호출은 견조한 상승세를 보였습니다.

### 2.2 영상 처리 및 비용 효율
*   **성공률 개선:** 전주 17%에 달했던 실패율이 이번 주 8.8%로 낮아졌습니다. 정책 위반이나 시간 초과 등 사용자 측면의 거부 사유가 줄어들고 시스템적 완주율이 높아진 결과입니다.
*   **실패율 분석 (총 10~11건 실패):**
    *   **yt-dlp 다운로드 실패 (6건):** 프록시 환경의 일시적 불안정으로 인한 다운로드 오류가 가장 큰 비중을 차지했습니다.
    *   **시간 초과 (3건):** 30분 제한 정책에 의한 자동 차단입니다.
    *   **검색 파싱 오류 (3건):** 유튜브 UI 변경으로 인한 `browseId` 획득 실패 사례입니다.
    *   **콘텐츠 정책 위반 (2건):** 부적절한 콘텐츠에 대한 AI의 생성 거부입니다.

### 2.3 시스템 오류 및 대응
*   **yt-dlp 오류 추적:** 다운로드 실패 건수가 6건으로 늘어난 만큼, 프록시 서버의 상태 모니터링을 강화할 필요가 있습니다.
*   **재정 현황:** 기간 내 신규 후원은 없었으며, 현재 1,400원 고정 환율로 운영 예산이 관리되고 있습니다. API 비용 증가 추세에 맞춰 후원 캠페인 노출을 검토해 볼 수 있습니다.

## 3. 종합 의견 및 제안
1.  **사용자 몰입도 분석:** TTS 호출량 급증은 고무적인 지표입니다. 사용자들이 어떤 장르의 영상을 주로 해설하는지 분석하여, 해당 장르(예: 영화, 강의 등)에 최적화된 프롬프트 튜닝을 진행하면 만족도를 더 높일 수 있습니다.
2.  **프록시 서버 안정화:** `yt-dlp` 오류는 서비스 신뢰도에 직결됩니다. 프록시 연결 실패 시 즉시 재시도(Retry)하는 로직을 보강하거나, 예비 프록시 노드를 확보하는 방안을 고려해야 합니다.
3.  **성공률 90% 유지 전략:** 이번 주 달성한 90%대 성공률을 유지하기 위해 기술적 오류(파싱, 다운로드)를 최소화하는 상시 모니터링 체계를 유지하겠습니다.
