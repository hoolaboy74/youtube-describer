네, 알겠습니다. 공인 IP를 사용하여 GCP ARM 우분투 서버에 애플리케이션을 배포하기 위한 전체 계획을 단계별로 안내해 드리겠습니다.

### **배포 계획: YouTube 화면 해설기**

이 계획은 **백엔드(Node.js)**를 `pm2`로 서비스하고, **프론트엔드(React)**는 정적 파일로 빌드하여 `Nginx` 웹 서버를 통해 서비스하는 표준적인 방식으로 구성됩니다. Nginx는 리버스 프록시 역할을 하여 모든 요청을 받아주고, `/api`로 시작하는 요청은 백엔드로 전달합니다.

#### **1단계: 서버 환경 설정 (필수 프로그램 설치)**

서버에 SSH로 접속한 후, 배포에 필요한 핵심 프로그램들을 설치합니다.

1.  **패키지 목록 업데이트 및 기본 프로그램 설치:**
    ```bash
    sudo apt update
    sudo apt install -y git nginx ffmpeg python3-pip aria2
    ```

2.  **Node.js (LTS 버전) 설치:**
    ARM 아키텍처에 맞는 Node.js를 설치합니다.
    ```bash
    curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
    sudo apt install -y nodejs
    ```

3.  **yt-dlp 최신 버전 설치:**
    시스템 파이썬 환경과의 충돌을 피하기 위해, 실행 파일을 직접 다운로드하여 설치합니다. (aria2c를 연동하여 고속 다운로드를 지원합니다.)
    ```bash
    sudo wget https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp -O /usr/local/bin/yt-dlp
    sudo chmod a+rx /usr/local/bin/yt-dlp
    ```

4.  **PM2 (프로세스 관리자) 설치:**
    Node.js 앱을 백그라운드에서 안정적으로 실행하고 관리하기 위해 PM2를 전역으로 설치합니다.
    ```bash
    sudo npm install -g pm2
    ```

#### **2단계: 소스 코드 배포 및 설정**

Git 저장소에서 소스 코드를 서버로 가져오고, 민감한 설정 파일들을 배치합니다.

1.  **소스 코드 클론:**
    홈 디렉터리에 소스 코드를 클론합니다. (URL을 실제 저장소 주소로 변경하세요.)
    ```bash
    cd ~
    git clone <저장소_URL> youtube-screen-describer
    ```

2.  **백엔드 설정:**
    -   백엔드 디렉터리로 이동하여 npm 패키지를 설치합니다.
        ```bash
        cd ~/youtube-screen-describer/backend
        npm install
        ```
    -   준비해 둔 민감한 파일들(`.env`, `my-tts-service.json`, `cookies.txt`)을 로컬 PC에서 서버의 이 디렉터리로 업로드합니다. `scp` 명령어를 사용하면 편리합니다.
        ```bash
        # 로컬 PC 터미널에서 실행
        scp .env my-tts-service.json cookies.txt <사용자명>@34.126.132.100:~/youtube-screen-describer/backend/
        ```

3.  **프론트엔드 설정 및 빌드:**
    -   (확인 완료) 프론트엔드 소스 코드(`App.js`)에서 API 요청 주소가 이미 상대 경로(`/api/...`)로 올바르게 설정되어 있습니다. 별도의 수정이 필요 없습니다.
    -   프론트엔드 디렉터리로 이동하여 npm 패키지를 설치하고 프로덕션용으로 빌드합니다.
        ```bash
        cd ../frontend
        npm install
        npm run build
        ```
        이제 `frontend/build` 디렉터리에 서비스할 정적 파일들이 생성되었습니다.

#### **3단계: Nginx 웹 서버 설정 (리버스 프록시)**

Nginx가 `34.126.132.100`으로 들어오는 요청을 받아 프론트엔드와 백엔드로 적절히 분배하도록 설정합니다.

1.  **기존 기본 설정 제거:**
    ```bash
    sudo rm /etc/nginx/sites-enabled/default
    ```

2.  **새로운 Nginx 설정 파일 생성:**
    ```bash
    sudo nano /etc/nginx/sites-available/youtube-screen-describer
    ```

3.  **설정 내용 작성:**
    아래 내용을 복사하여 붙여넣습니다. `<사용자명>` 부분은 실제 우분투 사용자 이름으로 변경해야 합니다. (예: `ubuntu`, `chacha` 등)

    ```nginx
    server {
        listen 80;
        server_name 34.126.132.100;

        # 기본 요청은 프론트엔드 빌드 파일을 서비스
        root /home/<사용자명>/youtube-screen-describer/frontend/build;
        index index.html;

        location / {
            try_files $uri /index.html;
        }

        # /api 로 시작하는 요청은 백엔드(Node.js)로 전달 (리버스 프록시)
        location /api {
            proxy_pass http://localhost:8080; # 백엔드가 8080 포트에서 실행 중이라고 가정
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_cache_bypass $http_upgrade;

            # SSE(Server-Sent Events)를 위한 설정
            proxy_set_header Connection '';
            proxy_buffering off;
            proxy_cache off;
            proxy_read_timeout 86400s; # 필요에 따라 시간 조절
        }
    }
    ```

4.  **설정 활성화 및 테스트:**
    -   새 설정을 활성화합니다.
        ```bash
        sudo ln -s /etc/nginx/sites-available/youtube-screen-describer /etc/nginx/sites-enabled/
        ```
    -   Nginx 설정에 문법 오류가 없는지 확인합니다.
        ```bash
        sudo nginx -t
        ```
    -   `syntax is ok` 메시지가 나오면 Nginx를 재시작합니다.
        ```bash
        sudo systemctl restart nginx
        ```

#### **4단계: 백엔드 서비스 실행 및 방화벽 설정**

1.  **PM2로 백엔드 서비스 시작:**
    ```bash
    cd ~/youtube-screen-describer/backend
    pm2 start index.js --name youtube-describer
    ```

2.  **서버 재부팅 시 PM2 자동 시작 설정:**
    PM2가 서버 재부팅 후에도 자동으로 서비스를 시작하도록 설정합니다.
    ```bash
    pm2 startup
    # 화면에 나타나는 명령어를 복사하여 실행 (예: sudo env PATH=...)
    pm2 save
    ```

3.  **방화벽 설정 (GCP & UFW):**
    -   **GCP 방화벽:** Google Cloud 콘솔에서 해당 VM 인스턴스의 네트워크 설정으로 이동하여, `http-server` (TCP 포트 80)와 `https-server` (TCP 포트 443) 트래픽을 허용하는 방화벽 규칙이 모두 적용되어 있는지 확인합니다.
    -   **서버 내 방화벽 (UFW):** 우분투의 방화벽을 설정합니다. `Nginx Full`은 HTTP(80)와 HTTPS(443)를 모두 허용합니다.
        ```bash
        sudo ufw allow 'OpenSSH'
        sudo ufw allow 'Nginx Full'
        sudo ufw enable
        ```

#### **5단계: SSL/HTTPS 설정 (Certbot 사용)**

Let's Encrypt의 무료 SSL 인증서를 발급받고 Nginx에 자동으로 설정하여 HTTPS를 활성화합니다.

**사전 조건:** 이 단계를 진행하려면 서버의 IP 주소에 연결된 도메인 이름(예: `your_domain.com`)이 있어야 합니다.

1.  **Certbot 설치:**
    Nginx 플러그인을 포함한 Certbot을 설치합니다.
    ```bash
    sudo apt install -y certbot python3-certbot-nginx
    ```

2.  **SSL 인증서 발급 및 Nginx 설정:**
    -   아래 명령어를 실행합니다. `your_domain.com`과 `www.your_domain.com`을 실제 도메인으로 변경해야 합니다.
        ```bash
        sudo certbot --nginx -d your_domain.com -d www.your_domain.com
        ```
    -   실행 중 나타나는 질문에 답변합니다.
        -   **이메일 주소:** 인증서 갱신 알림용.
        -   **서비스 약관 동의:** (A)gree
        -   **HTTP -> HTTPS 리디렉션:** **2번(Redirect)**을 선택하는 것을 강력히 권장합니다.

3.  **자동 갱신 확인:**
    -   Certbot은 `systemd.timer`를 통해 자동으로 인증서를 갱신합니다. (`crontab`에는 등록되지 않습니다.)
    -   아래 명령어로 타이머의 상태를 확인할 수 있습니다.
        ```bash
        systemctl status certbot.timer
        ```
    -   갱신 프로세스를 테스트하려면 다음을 실행합니다.
        ```bash
        sudo certbot renew --dry-run
        ```

**2. Nginx 및 SSL 설정:**
- 기존 `mom` 서버에서 `nginx` 설정 파일(`youtube-describer`)과 `/etc/letsencrypt` 디렉토리 전체를 `komom` 서버로 복사했습니다.
- Nginx 설정의 초기 검증 단계에서 IP 주소로 직접 접속 가능하도록 임시 변경했으나, 이후 운영 환경 설정으로 되돌렸습니다. (HTTP 요청은 `https://blindmom.org`로 301 리디렉션되도록 변경하고, `server_name`에서 IP 주소를 제거)
- SSL 인증서 파일(`/etc/letsencrypt` 디렉토리)은 기존 서버와 동일함이 파일별 체크섬 비교를 통해 확인되었습니다.
- Certbot의 자동 갱신(`certbot.timer`)은 새 서버에 이미 올바르게 설정되어 활성화된 상태입니다.

**3. 백엔드 애플리케이션 설정:**
- `pm2`를 사용하여 백엔드 애플리케이션(`youtube-describer`)을 시작하고, 서버 재부팅 시 자동으로 시작되도록 설정했습니다.
- `SqliteError: unable to open database file` 오류가 발생하여, `/app/youtube-describer/backend/db` 파일이 디렉토리로 잘못 생성된 것을 발견했습니다. 해당 파일을 삭제하고 디렉토리로 재 생성하여 문제(데이터베이스 접근 권한)를 해결했습니다.

**4. 시스템 모니터링:**
- `sysstat`를 설치하고, 데이터 수집 간격을 기존 10분에서 5분으로 변경하여 설정했습니다.

**주의사항:**
- SSL 인증서 자동 갱신이 정상적으로 작동하려면 `blindmom.org` 및 `www.blindmom.org`의 DNS A 레코드가 새로운 서버의 IP 주소 (`34.50.63.229`)를 가리키도록 업데이트되어야 합니다. DNS 변경이 완료되면 `https://blindmom.org`로의 접근이 정상적으로 이루어질 것입니다.
