# Gemini Flash 프롬프트 반복 실험 — 2026-09-08

## 결론

gemini-3.8-flash로 v13에서 파생한 v14·v15·v16을 총 5회 새로 실행했다. 이번 결과에서는 어느 수정본도 v13보다 전반적으로 우수하다고 인정하기 어렵다. v13을 비교 기준으로 유지하고 새 버전의 backend 적용은 보류한다. v13 자체도 시각적 근거 오류가 있어 완성본이라는 뜻은 아니다.

모든 변경은 test_scripts의 새 프롬프트 파일과 결과에 한정했다. backend 프롬프트·코드·DB는 수정하지 않았다. DB는 test_scripts 기준 ../backend/db/cache.db를 sqlite3 -readonly로 조회했다. 가족 영상 외에 DB의 완료된 635초 항공 사건 설명 영상을 선택했다. 두 영상 모두 기존 asset 캐시를 재사용했고 추가 정보 수집이나 다운로드는 하지 않았다. 기존 비교 스크립트의 영상 메타데이터 조회는 수행됐다.

## 실험

모델은 모두 gemini-3.8-flash, temperature 0.7, MEDIA_RESOLUTION_LOW. 각 후보/영상당 1회이며 v13은 기존 실행을 사용했다. 생성 시간은 API 호출 시간이지 전체 준비 시간은 아니다. 항목 수·txt 수는 품질 점수가 아니다.

## 무엇을 바꿨나

- v14: v13 전체를 보존하고 출고 전 출처·동사·청취 가치 점검을 추가. 말로 아는 사건을 보이는 동작으로 바꾸지 않도록 구체화.
- v15: v13의 긴 집필 절차·가상 사례를 짧은 원음/이미지 정보 분리 절차로 재구성. 장르별 목적, 유용한 반응, 원음 중복 금지는 유지.
- v16: v13으로 되돌아가 입력 데이터 뒤에 최종 집필 계약을 추가. 대사 없이도 행동을 이미지에서 확인할 수 있는지 재확인하도록 강조. 이름 등 확정된 지칭은 문맥 사용을 허용.
- 특정 영상의 이름·정답·타임스탬프를 프롬프트에 삽입하지 않았다. 출력 태그와 필요한 독립 OCR의 직접 읽기 원칙을 유지했다.

## 가족 영상: 자연스러움과 사실성은 별개

v13은 장면을 이야기 흐름으로 잘 이어 주지만, 원음 내용을 시각적 행동으로 재구성하는 문제가 있다. v14~v16의 추가 규칙도 이를 안정적으로 해결하지 못했다.

| 확인 지점 | 이미지 근거 | 결과 비교 |
|---|---|---|
| 238초 | frame-0121: 리후는 이미 가방을 들고 멀리 서 있고 전경에는 어른 손의 카드형 물건 | v13의 가방을 건넨다는 묘사는 근거 부족. v16은 가방을 든 상태로 개선했지만 물건의 지갑 확정은 신중해야 함 |
| 424초 | frame-0214: 팔과 천장, 구매 여부를 묻는 글자. 아이스크림을 꺼내는 과정이 보이지 않음 | v13·v14·v15·v16 모두 꺼내 주는 동작을 생성. v15는 쭈쭈바로 더 구체화하기까지 함 |

v15는 이름 리후를 쓰지 않고 '아이'를 반복하고, 64초에서 젓가락을 숟가락으로 바꾸며 '생각에 잠깁니다'를 추가했다. 간결화 자체가 정확성과 인물 지칭을 개선하지는 않았다.

v16의 470초 '활짝 웃습니다'는 유용한 반응 후보지만, 이것 하나로 전체 품질 향상을 선언할 수 없다. 웃음의 청취 가치는 실제 원음과 함께 평가해야 한다.

## 항공 사건 설명: OCR이 핵심 정보

이 영상은 지도·접근 차트·시뮬레이션·화면 설명 글자가 많은 다른 유형이다. 가족 영상처럼 txt를 줄이는 방향은 적절하지 않다.

- v13은 50초 '259.5mm', 56초 '다음 날 255.5mm', 60초 인명 피해, 66초 특별재난지역 선포를 각 표시 시각에 나눈다.
- v15는 50초에 56초 글자까지, 60초에 66초 글자까지 미리 합쳤다. frame-0027/0030/0032/0035와 대조하면 서로 다른 이미지 정보다. 압축이 타이밍을 훼손했다.
- v16은 위 두 조기 병합을 피했지만 56초 수치를 생략했다. 428초에는 아직 점진적으로 표시 중인 설명을 완결해 미리 읽는다. frame-0216에는 문장 전체가 보이지 않는다.
- v16 470초 '화면 왼쪽에 풍속 10노트를 가리키는 계기'는 frame-0237에서 확인되지 않는다. 실제로는 항공기 외부와 관제 교신 글자다. 단순 문체 문제가 아니라 잘못된 시각 정보다.
- v16 342초는 화면의 '부기장 진술' 표지를 생략했다. 누가 한 판단인지가 중요한 사건 설명에서는 출처를 보존하는 편이 좋다.
- v16은 뉴스 글자를 v1로 바꾸거나 교신 자막이 표시된다는 사실만 말하기도 한다. 필요한 글자는 txt로 직접 읽으라는 요구와 맞지 않는다.

원음 분류는 foreign이나 대사 트랙 42개가 대부분 [Music]와 'so'이다. 실제 오디오를 청취하지 않았으므로 교신 글자가 독립 재현 텍스트인지 실제 외국어 교신의 번역인지 단정하지 않았다. v16이 교신을 많이 생략한 것을 원음 중복 방지의 성공으로 계산하지 않는다. 이 구간의 txt/trans 적격성은 별도 청취 확인이 필요하다.

## 검증과 한계

- 비교 스크립트 결정적 테스트 15/15 통과.
- v14·v15·v16은 placeholder 치환 후 korean/foreign/mixed/unknown의 4가지 정책 로딩 검사 통과. 템플릿 자체를 치환 없이 검사한 최초 호출은 unresolved placeholder로 실패했으며, 올바른 로딩 경로로 재검증했다.
- 표의 7개 결과 모두 현재 canonical 검사에서 전 항목 accepted, rejected/quarantined 0. 검증기가 이미지 의미 오류를 잡았다는 뜻이 아니다. 위의 잘못된 동작·시각·OCR 분류가 그대로 통과했다.
- 각 영상 안에서 비교 실행의 frames와 dialogueTrack은 동일했다. 가족 프레임 SHA256: 5a815d94a3ee4322eb2587d702a0e2fcd1b66bf98a7b15abc4eb34a2cf3b78e8. 대사: 6d9e44a2e9ce1dddc1e826c2fd2c04a3865620f4e366231a7d9aa8f2fbb23ff9.
- 항공 프레임 SHA256: 8e8458270ab92b95fd8d4643d8ef917bce50497c3b45aff91fe435ddb0351ada. 대사: 3b0801c5627f5da23510cf82a89456e39c0f15b1504ad07a2005d5aab7f56ee9. 해시는 input_context의 해당 배열을 JSON.stringify한 값 기준.
- 두 영상·후보별 1회인 소규모 실험이다. 생성의 변동성이 있으므로 차이를 전부 프롬프트 효과로 해석하지 않는다. 원음/TTS 청취 및 시각장애인 사용성 평가는 하지 않았다. 항공 전문 내용의 외부 사실 검증이 아니라 입력 대비 해설 품질을 비교했다.

## 다음 실험 방향

새 버전 번호를 올리는 것을 개선으로 간주하지 않는다. v13을 고정 기준으로 두고, 다음은 한 번에 한 문제만 바꾸어 같은 조건에서 반복 검증하는 편이 좋다: 대사 기반 동작 추정, OCR 표시 시각, 글자 출처·태그 유지. 유용한 반응·공간 연결·필요 OCR 누락도 동시에 감시해야 한다. 이번 결과로 Flash 전체의 능력 한계나 프롬프트 개선 불가능을 확정할 수는 없지만, 규칙을 더 쓰거나 짧게 만드는 것만으로 안정적으로 해결되지는 않았다.
