## 필요한 글자와 중복 낭독의 구분

OCR로 읽을 수 있는 글자는 제거 대상이 아닙니다. 청취자에게 새로운 정보를 주는지가 기준입니다.

- 이름표·안내판·수치·조건·메시지·슬라이드: 내용 이해에 필요하면 전달합니다.
- 편집자의 상황·정서 설명: 원음에 없는 맥락이면 전달하며, 제작자의 설명임을 밝혀 내면을 단정하지 않습니다.
- 실제 발언·혼잣말·음성 안내를 옮긴 한국어 자막: 원음에 있으므로 다시 읽지 않습니다.
- VTT에 없다고 곧바로 독립 글자로 취급하지 않습니다. 반대로 비슷한 단어가 있다는 이유로 주체와 의미가 다른 편집 설명을 모두 제거하지 않습니다.

예를 들어 '아빠의 음성에 안도감을 느끼며…'라는 제작자 설명은 유용한 맥락일 수 있습니다. 반면 v10 재실행의 52초 '손을 흔들어 보라는 글자', 458초 '이제 가방에 넣는다는 자막', 500초 '비밀번호를 눌러달라는 안내'는 대사·안내를 되읽을 위험이 큽니다. 동일 편집 설명이 미리보기와 본편에 반복되는 것도 억제해야 합니다.

## 백엔드 실패 원인과 검증의 한계

`aKwJnvRJqRw`의 2026-09-07 16:06:44 실패와 대응되는 로컬 DB 격리 기록에서 다음과 같은 원문을 확인했습니다.

`0[txt] 너진짜좋아해 ㅜㅜ\n내가그렇게싫어?…`

시간에 대괄호가 없고, 실제 줄바꿈 대신 역슬래시-n이 포함되어 있습니다. 백엔드가 요구하는 `[0][txt] 문장` 형식과 달라 정상 이벤트로 해석되지 않았습니다. 같은 원문에서 태그·시간·내용·출처 오류가 연쇄적으로 발생했으며, 유효 이벤트가 하나도 없어 `canonical_output_unavailable`로 처리되었습니다. **화면 글자를 읽었다는 이유로 실패한 것이 아닙니다.** 모델 호출은 이루어졌으므로 실패하더라도 API 비용은 기록됩니다.

관련 코드: `backend/modules/canonicalOutput.js`의 `parseLegacyLine`, `backend/videoProcessor.js`의 `canonicalizeModelOutput` 및 accepted 이벤트 없는 경우의 실패 처리.

별도로 현재 canonical 검증은 timestamp <= 0을 거부합니다. 따라서 올바른 형식의 0초 항목도 제외됩니다. 마지막 v10 결과는 56개 통과/1개 거부, v8 결과는 31개 통과/1개 거부였으며 거부 사유는 모두 0초의 `TIMESTAMP_OUT_OF_RANGE`입니다. 이 규칙은 수정하지 않았습니다.

canonical 통과는 형식·정책 검사의 결과이지 화면과 의미가 정확하다는 보증이 아닙니다. 위의 시각 오인과 대사 중복 상당수는 이 검사로 차단되지 않았습니다. v8~v11의 프롬프트 파일 자체는 정책 로더 검사에 통과했지만, 이것 역시 생성물의 품질 보증과 다릅니다.
